# FDE X 战略 Agent 项目分享包

本包提供欢乐互娱的企业需求、公开战略方法说明和模拟开发资料。项目面向 K12 游戏化英语教育，使用通用 Agent 与 lark-cli，至少支持 Codex 和 Claude Code。

## 阅读入口

1. [需求提报表](需求提报表.md)：供社区对接人了解业务背景、项目目标、输入、交付物和评价标准。
2. [学生材料说明](学生材料/README.md)：模拟知识库、任务卡、开发参考和输出模板的使用入口。
3. [战略 PPT 样板](学生材料/输出模板/年度战略草案-橙白框架样板.pptx)：橙白框架风格，可编辑虚构案例。
4. [战略方法与公开来源](学生材料/战略方法与公开来源.md)：公开方法依据及业务适配。

可直接分享本文件夹或完整压缩包。单独转交学生材料时，同时附上根目录提报表；学生版压缩包已包含二者。

## 交付格式

年度战略草案为可编辑 PPT（.pptx），包含研究发现、战略选择、年度推进、首季验证和执行审视，附录保留来源依据。另交付可复用 Agent 工作流、接入说明及运行记录。具体内容与评价要求以根目录提报表为准。

## 项目范围

交付支持 Codex、Claude Code 的战略研究工作流及提报表列出的成果，以模拟飞书沙箱和真实联网完成验收。企业真实知识库试跑属于后续应用。社区导师帮助学生解读需求。

模拟公司、访谈、竞品和测试数字均为虚构；企业内部知识及访问凭据不随包提供。实施顺序、配置和模板用于帮助开发，项目交付标准以提报表为准。

# T00 · 企业真实业务任务说明

| 项目 | 内容 |
| --- | --- |
| 行业与业务 | K12 英语教育，使用游戏化方式完成英语教育，研运一体 |
| 当前阶段 | 研发／免费试点 |
| 现有数据 | 尚未沉淀产品试点数据，经营数据、预算、可用人力资料尚未形成 |
| 使用人 | 专门从事战略研究的同事 |
| 规划周期 | 运行开始日起未来 12 个月，运行时填写具体起止日期 |
| 已有知识 | 飞书知识库中的用户调研、竞品标杆、行业／AI 信息、产品知识、讨论和复盘 |
| 路线图地位 | 可重新讨论的设想，允许连同目标、顺序和依据一起评估 |
| 运行环境 | 通用 Agent，至少支持 Codex 与 Claude Code；飞书通过 lark-cli 访问 |
| 核心任务 | 自动获取结构化外部背景知识，结合内部资料形成公司级规划和验证方案 |
| 业务成果 | 可编辑年度战略 PPT（.pptx，含研究依据附录、年度执行与验证安排）；实际运行记录。附录按正文页码与具体结论关联证据 |
| 授权资料入口 | 企业对接人在启动本任务时提供资源清单；运行负责人按开发与运行说明完成映射和预检，缺授权则阻断企业模式，不复用模拟事实 |

研究覆盖目标客群、优先市场、学习价值、产品与收费路径、能力建设及投入条件。尚无结论的事项进入备选比较，资源未知时形成条件方案。企业对接人组织真实业务评审，运行参数与缺口处理采用[开发与运行说明](../%E5%BC%80%E5%8F%91%E4%B8%8E%E8%BF%90%E8%A1%8C%E8%AF%B4%E6%98%8E.md)。

## 输入映射

| --- | --- | --- |

| 方法与判断规则 | 方法说明、T01、K05 | 当前阶段、可重议事项、既有承诺与不允许动作；资源未知时说明未知 |
| 历史案例 | K03、K04、K06、K07 | 历史讨论、路线图或复盘有则提供；不将旧方案默认当成当前承诺 |

## 切换到真实任务

1. 新建独立运行目录与配置，取消模拟资料输入范围。
2. 使用企业授权的飞书资源映射，不能仅更换公司名称后沿用虚构证据。
3. 按需读取资料与关联表格／图表，保留出处和日期。
4. 区分当前事实、历史讨论、预测和已作决定；对资料冲突先提出解释和必要问题。
5. 企业尚无试点沉淀时，以验证设计和数据采集作为输出，不把模拟库的任何数字填进真实规划。
6. 战略研究同事核查事实与证据，企业指定评审人评价路径取舍和资源建议。

## 最少需要登记的运行信息

- 运行日期、规划起止、资料截止日、研究预算。
- 授权资料范围与当前有效的产品状态说明。
- 需要比较的战略问题、已有承诺或边界；仍开放的事项明确作为研究问题。
- 本轮评审角色、材料用途和可分享范围。

企业应用启动前，由企业运行负责人校验授权清单、工具、日期和预算。未具备授权或工具就停止企业模式，并向对接人提交具体阻断项；恢复条件满足后新建运行，不用模拟数据顶替真实资料。业务预算和效果记录不存在时，按开发与运行说明产生条件方案与关闭动作。

# 开发与运行说明

本说明定义战略 Agent 的运行方式与交付记录，业务要求与 KR 标准见[需求提报表](../需求提报表.md)。随包资料为开发输入与输出参考；项目成果为学生实现的工作流及两端实际运行结果。

## 开发顺序

1. 读取 [T01 模拟任务卡](任务卡/T01-模拟年度规划.md)，用本地模拟资料建立读取、研究、证据整理和战略分析流程。
2. 按[导入说明](模拟知识库导入飞书说明.md)部署独立飞书沙箱，接入真实 lark-cli 与互联网工具。
3. 在 Codex、Claude Code 中分别从原始任务完整运行，处理资料冲突、读取失败和资源约束。
4. 对照提报表整理成果、共用工作流和两端安装、配置、启动及维护说明。

两端共用业务规则、模板与必要脚本，通过工具适配和独立入口处理环境差异。工作流由使用者手动触发，实现形式由项目组选择。

## 运行模式与环境

| 模式 | 资料来源 | 用途 |
| --- | --- | --- |
| offline_fixture | 本地模拟库与虚构外部快照 | 开发解析、推理和输出逻辑 |
| lark_live | 独立飞书沙箱与真实互联网 | 学生正式验收 |
| enterprise_live | 企业授权知识与真实互联网 | 验收后企业应用，使用 [T00](任务卡/T00-企业业务任务说明.md) |

两端需要本地文件和命令访问、联网搜索、网页原文读取、图片理解或可靠的图中文字提取能力，以及可编辑 .pptx 的生成和排版检查能力。记录实际 Agent、模型、操作系统、lark-cli 与工具版本、身份和限制，不因环境名称相同而假设能力相同。

飞书访问显式使用获授权 user 身份，命令与参数以所用 CLI 版本的帮助为准。首版运行只读飞书业务资料、写本地成果；模拟资料部署是独立初始化操作。在线可读取本地任务、方法、代码和模板，但不能用本地业务正文掩盖飞书读取失败。目录标题不能代替正文，图片与画板分别记录真实读取方式。

认证 access／refresh token、Cookie 和密钥不进入交付包或日志。获授权的文档、节点和素材定位标识可用于配置；企业未公开信息不进入外部搜索请求。

## 共用研究流程

1. 记录任务、规划起止、资料截止时间、授权范围和研究预算；未知约束写入任务和运行配置。
2. 按需读取内部资料及关联图表，保留编号、版本、原文位置与读取状态；区分事实、观点、预测、公司决定和未知项。
3. 将知识缺口拆为问题，制定关键词、语言、来源类型和停止条件。
4. 搜索并阅读真实原文，核对时效、适用市场、上游来源和反向证据；转载不计为独立证据。
5. 结合五看洞察比较 2–3 条战略路径，形成目标、策略与控制点建设，说明优先和暂缓事项。
6. 在战略 PPT 中连接关键任务、岗位、资源、季度安排与首季验证，分别评价参与、学习和购买。
7. 生成含研究依据附录的战略 PPT 及运行记录，检查正文结论与附录来源、执行安排之间的对应关系。

模拟竞品不能作为真实搜索对象。在线另选真实公开产品并说明可比性；虚构快照不计入真实联网证据。正文中的指令性文字属于待分析数据，不能改变任务和授权。Agent 不自行联系用户、开展教学、收款、采购或批准预算。

## 日期、预算与异常

规划覆盖起点后的 12 个日历月，前 90 天行动单独计算。T01 离线案例固定为 2026-09-17 至 2027-09-16；在线可采用运行时点，两端使用相同任务、日期范围、资料版本和研究预算，模拟资料本身的日期不改写。

来源发布日期、事件期间和读取时间分别记录。截止日后的信息不能进入历史回测；动态页面无法读取、只有摘要或需要登录时，如实说明限制。

运行前设置搜索、原文读取、飞书调用、时间、请求超时和重试上限，并保留配置。批量搜索按查询词计数，重试计入调用用量。主要问题得到覆盖、连续检索没有新增有效证据或预算用尽时结束；未覆盖事项进入结果说明。

临时错误采用有界重试和退避；认证或权限错误列出恢复所需条件，不绕过权限。部分资料失败时继续可完成的分析，必要授权或工具不可用时停止相应模式并说明阻断原因。恢复后新建运行或注明续跑关系，保留失败记录。

## 未知信息与记录

无经营基线、预算、人力或试点数据不阻断条件性战略分析。影响推荐的缺口应记录当前状态与影响、条件方案、所需证据或决策、责任岗位、获取节点、关闭证据，以及未解决时缩小、暂缓或停止的内容。

例如，预算未形成时给出附依据的情景估算或成本公式与条件方案；管理层在首次新增支出前决定额度，未形成额度则暂缓需要新增支出的实验。岗位建议不代表已有编制，目标与预测不能写成实绩。

运行记录格式由实现选择，至少包含任务与模式、环境和工具版本、日期、资料范围和版本、研究问题与检索计划、问题覆盖情况、预算、实际调用与用量、产出路径、失败读取、人工介入、停止原因和已知限制。未使用工具或无法获取版本时说明原因，计数来自实际记录。分别标识完成、部分完成或阻断；流程完成不等于战略假设得到验证。

## 启动与双环境验证

运行配置包含模式、任务文件、规划日期、资料截止时间、研究预算、授权范围与输出目录。两端使用相同任务、日期、资料版本和预算，在独立任务及结果目录中运行。离线开发读取本地 manifest 与虚构快照；正式验收读取实际飞书资源映射并开展真实联网研究。

两端各自从原始资料生成含研究依据附录的战略 PPT，保留完整调用与异常记录。推荐和文字可以不同，评价采用相同的 KR1／KR2／KR3 标准。共同工作流及该端记录构成交付物 2 的评价依据。

| 验证内容 | 记录与判断依据 |
| --- | --- |
| 完整运行与信息增量 | 实际联网、原文和飞书关联资源读取记录；新增信息、五看三定、正文结论与证据附录的对应关系 |
| 证据与数据缺口 | 同源、过期、冲突、空研究入口及无经营基线的处理；输入文字未改变任务或权限 |
| 资料更新 | 沙箱文档更新后的重读记录；缓存或搜索索引延迟的识别与影响 |
| 异常处理 | 两端分别记录授权过期、权限不足、限流和不可访问的验证结果；重试有上限，失败有原因及恢复条件 |
| 迁移与约束变化 | 更换同类议题或目标市场、调整资源约束后的结果；核心工作流共用，策略随证据和约束变化 |
| 可复现与效率 | 安装、配置、运行、更新步骤，以及实际耗时和人工介入；未取得人工基准时不计算节省比例 |

异常场景可采用获授权的测试配置或故障模拟，记录注明触发方式；正常全流程须使用真实飞书访问与真实联网。

# 华为战略方法调研与游戏化英语教育应用

调研日期：2026-09-17。用途：为 FDE X 企业年度战略 Agent 项目提供方法依据及业务适配说明。

企业面向 K12 英语教育，以游戏化方式开展教学，采用研运一体模式。战略研究同事通过通用 Agent 开展研究，至少支持 Codex 和 Claude Code；企业知识库维护在飞书云文档与 Wiki 中，由 lark-cli 访问。项目重点是建立结构化的互联网背景研究流程，并将研究结果与企业知识结合，用于公司级年度战略规划。

## 1. 项目定位

**游戏化英语教育公司年度战略 Agent（通用 Agent + lark-cli）**。

核心业务链路：提出公司年度战略任务 → 盘点企业已有知识 → 自动开展市场、用户、竞品标杆及 AI 背景研究 → 核验与整合证据 → 比较战略方向 → 输出包含年度执行与验证安排的战略 PPT，附录保留研究依据。

现有知识来源包括竞品调研 Wiki、用户调研 Wiki、行业信息 Wiki、竞品分析、AI 前沿信息、内部产品知识和项目复盘。已有知识用于明确研究起点；Agent 需要主动补充新资料、核对时效并识别知识缺口。

公司处于研发／免费试点阶段，尚未沉淀产品试点数据及经营、预算、人力资料。规划为启动日起未来 12 个月；现有长期路线图可重议。无经营基线时，业绩差距不能凭空量化，应侧重机会假设、能力缺口及分阶段验证。

规划以公司整体为对象，将客群与市场、学习价值、产品、增长、商业模式、AI 应用和组织能力联系起来。最终战略选择与资源承诺由管理层作出。

## 2. 公开战略方法依据

### 2.1 客户价值、战略聚焦与边界

华为发布 2017 年年报时强调，关注客户数字化转型中的现实挑战，帮助客户解决问题并实现商业成功。[华为：2017 年年报发布说明](https://www.huawei.com/cn/news/2018/3/huawei-2017-annual-report)

华为 2017 年年报中的战略说明明确表达业务聚焦，以及做什么和不做什么的边界。该材料反映当时战略，不作为今天各业务范围的判断。[华为 2017 年年度报告，英文版正文第 3 页](https://www.huawei.com/-/media/corporate/pdf/annual-report/annual_report2017_en.pdf)

**本项目的转化建议**： 每个候选方向必须说明服务哪类学习者、解决什么学习问题、靠什么形成差异，以及暂缓什么。仅写“打造优质教育产品”“拥抱 AI”“全球化布局”不构成可评审的选择。

### 2.2 BLM：把战略设计与执行条件放在一起

IBM 的原始资料给出了 Business Leadership Model：战略侧包括市场洞察、战略意图、创新焦点、业务设计；执行侧包括关键任务及依赖、人才、正式组织、氛围与文化，并连接市场结果和差距。领导力与价值观贯穿其中。因此，BLM 不能被标为华为原创。 [IBM Redbooks，图 1-2，正文第 5 页](https://www.redbooks.ibm.com/redpapers/pdfs/redp4374.pdf)

关于 IBM 实践的研究进一步区分：业绩差距是预期与实际结果的差异；机会差距是现有业务与可通过新业务设计获得的结果之间的差异。 [Harreld、O’Reilly、Tushman：Dynamic Capabilities at IBM，2007](https://digicoll.lib.berkeley.edu/record/284764/files/991056723509706532_C095180123_49_4.pdf)

**本项目的转化建议**： 先判断议题是改善现有教育业务表现，还是探索新的增长机会，再检查对应能力与资源。“获客成本高”本身不足以支持开发新产品的结论。本项目依据公开可核验的框架设计分析流程，不涉及华为内部模板。

### 2.3 五看三定：便于组织调研的问题清单

公开咨询资料通常将“五看”概括为看行业／趋势、看市场／客户、看竞争、看自身、看机会；“三定”的常见表述是定目标、定策略、定控制点。不同公开材料措辞并不完全一致。本项目采用这一公开实践口径组织提问与分析。 [安谋咨询：五看三定方法论解读（二手资料）](https://www.niuhrd.com/articles/shen-du-chai-jie-hua-wei-zhan-lve-dong-cha-he-zhan-lve-gui-hua-wu-kan-san-ding-fang-fa-lun)

“控制点”在本项目中解释为支撑持续差异化的关键能力或资源，例如内容生产能力、学习者社区与服务能力或渠道能力。它不是报告里随意填入的一句“建立壁垒”，需要已有证据或建设计划。

### 2.4 DSTE：战略要落到年度计划、预算和复盘

华为 2017 年年报直接说明：DSTE 管理体系通过愿景牵引战略，让战略驱动年度业务计划、预算和绩效，并通过战略解码与执行审视推动落地。 [华为 2017 年年度报告，英文版正文第 122 页](https://www.huawei.com/-/media/corporate/pdf/annual-report/annual_report2017_en.pdf)

**本项目的转化建议**： 输出必须连接到目标、任务、岗位、资源、时间和复盘条件。首版只形成这些内容的建议稿，公司年度目标需连接季度里程碑与首季验证。年度规划和 90 天行动安排属于本项目的业务设计，并非华为固定规范。

### 2.5 四组概念如何连接

五看用于洞察，三定用于归纳战略选择；BLM 将这些选择与战略意图、创新焦点、业务设计及执行支撑连接；DSTE 将选择解码到年度计划、预算、组织目标和执行审视。它们在本项目中形成一条分析链，不是四套相互独立、重复填写的表格。

三定需要相互匹配：目标说明预期结果和衡量方式；策略说明实现路径、备选比较及不做事项；控制点说明支撑持续差异化的关键能力或资源、现状证据、建设动作及证明标准。控制点不是项目进度检查点，普通功能也不自动构成竞争优势。

本项目处于研发／免费试点阶段，不强行套用成熟企业的收入指标、预算体系或组织规模。管理层承担战略取舍和资源决策，岗位建议不等于实际编制。用指标口径、基线建立方案、条件投入和季度审视形成可执行的首版；目标、判据和资源未形成时，明确制定岗位、决策节点和未形成时的处理。

## 3. 战略方法如何用于 K12 游戏化英语教育

以下为项目适配设计，不是华为内部流程复刻，也不构成对某一教育产品学习效果的判断。

| 视角 | 研究重点 | 需要形成的判断 |
| --- | --- | --- |
| 行业／趋势 | 英语教育需求、教育科技与 AI 变化、目标市场环境 | 哪些变化影响公司的年度选择，哪些仅是短期热点 |
| 市场／用户 | 学习者年龄与能力、学习场景、使用障碍、付费及决策角色 | 服务谁、解决什么学习问题、如何验证学习与购买价值 |
| 竞争／标杆 | 同类教育产品、替代学习方式、值得借鉴的产品或运营机制 | 用户为什么选择我们；标杆哪些做法适用、哪些条件不具备 |
| 自身 | 产品知识、教研与研发能力、运营能力、项目复盘、经营与资源约束 | 哪些优势已得到验证，哪些能力要补，能支持多大范围的投入 |
| 机会 | 将外部证据与内部能力关联 | 本年度应优先投入、先验证、暂缓或放弃什么 |

研究必须区分三类结果：**学习结果**、**使用参与** 和 **经营表现**。它们可能相互影响，但不能直接互相替代。例如，用户愿意多玩一段时间不等于英语能力已提升；访谈中表达喜欢也不等于愿意持续付费。

学习者、实际使用者和付费决策者可能不同。依据本轮用户研究识别这些角色，不预设家长、学校或学习者本人是唯一购买方。研究任务写清候选地区、学段和收费路径；没有定下的事项进入比较，不要求先作出战略选择才启动研究。

## 4. 互联网背景研究的结构化流程

| 环节 | 工作要求 | 输出 |
| --- | --- | --- |
| 研究任务定义 | 明确规划年度、战略问题、市场、客群、截止日与检索预算 | 年度任务卡与问题清单 |
| 内部知识盘点 | 检索相关 Wiki，分清事实、旧判断和未验证假设 | 已有知识摘要与缺口 |
| 研究计划 | 将缺口拆成子问题，设关键词、语言、来源类型和完成条件 | 可执行检索计划 |
| 外部检索与阅读 | 自动找来源并读取原文；搜索摘要用于定位线索 | 原始来源记录与摘录 |
| 核验与去重 | 识别转载、过期资料、宣传内容、样本与口径差异 | 可用事实、冲突与适用范围 |
| 结构化整理 | 将发现关联研究问题、飞书知识及原始依据 | 研究发现与 PPT 证据附录 |
| 战略解释 | 说明对公司的机会、威胁和关键假设 | 年度规划输入与验证问题 |

PPT 来源附录至少记录：来源编号、标题、URL／飞书文档链接、发布者、发布日期、事件或数据期间、读取时间、原文位置、适用市场与用户、支持的事实、限制。时间未知时明确标注，不以访问日期代替发布日期。

关键判断优先依靠原始研究、主管机构公开资料、产品官方文档和正式披露。多家媒体转述同一上游材料不构成多份独立证据；只有单一来源的判断需保留局限。公开评论补充用户线索，但不替代企业真实用户调研，也不触发自动联系受访者。

研究按问题覆盖与增量价值停止：完成主要问题、连续检索无新增有效证据，或达到本轮任务预算时结束，报告未覆盖事项。不得为了数量凑来源，也不得因存在知识缺口无限检索。

每次运行生成独立战略 PPT 和运行记录，保留资料时间范围及来源，不自动覆盖原 Wiki。首版由战略研究同事手动触发；有新证据或约束变化时发起新运行，不要求后台定时监控。

## 5. 从背景研究进入公司年度规划

1. **识别核心差距**：区分当前业务表现问题与新增机会，避免从某条热点直接跳到公司战略。
2. **设定战略议题**：把背景发现转成必须作出的选择，例如优先服务哪个细分客群、优先改善哪类学习价值、哪种 AI 能力值得投入。
3. **比较备选路径**：对重要议题提出 2–3 个不同选项，比较用户价值、经营逻辑、能力匹配、投入和风险；证据不足时先安排验证。
4. **形成公司年度主线**：明确优先事项和不做事项，检查产品、增长、技术与组织是否争用同一资源。
5. **建立目标与推进安排**：年度目标对应关键任务、季度里程碑、负责人岗位和资源条件；目标数值须有依据；无法确定时在战略 PPT 中说明制定责任、节点及未形成目标时的处理，依据列入 PPT 附录。
6. **制定首季验证**：围绕影响年度取舍的关键假设安排前 90 天行动，说明何时继续、调整或停止投入。

**虚构示例**：公开资料显示某标杆增加了 AI 互动练习，内部用户研究提示反馈不够及时。可以据此提出“即时反馈是否能改善目标学习任务”的假设，安排小规模验证；不能仅凭标杆发布了功能就判断本公司应全面投入，也不能将互动次数当成学习效果。

### 年度战略成果的组织方式

成果按公开 BLM 的战略设计和执行要素组织，并结合华为公开 DSTE 原则连接年度计划。以下为本项目的交付结构，不是华为内部模板。

| 方法环节 | 具体输出 |
| --- | --- |
| 业绩／机会差距 | 当前结果与目标差距、潜在机会及依据；无数据时保留待验证问题 |
| 市场洞察 | 五看研究结论、机会与威胁、关键证据和冲突 |
| 三定与战略意图 | 年度方向、目标口径与成功判据、实现策略及取舍、控制点与能力建设路径 |
| 创新焦点 | 学习体验、产品、技术或商业模式的重点突破与试验 |
| 业务设计 | 客户选择、价值主张、价值获取、活动范围及持续优势 |
| 关键任务与依赖 | 将业务设计拆成关键举措，说明先后关系和跨岗位依赖 |
| 执行支撑 | 组织职责、人才与能力缺口、需要建立的协作机制和文化行为 |
| 年度业务计划与执行审视 | 指标基线与目标、预算人力、季度里程碑、首季行动；对照目标与实际审视偏差，调整路径与资源并保留依据 |

战略草案以可编辑 PowerPoint（.pptx）交付，包含战略总览、按上述逻辑展开的分析页面，以及相互对应的年度计划和资源表。不能仅罗列框架名称：每项选择必须说明依据、放弃的选项和执行条件；目标、任务、责任岗位、资源及复盘使用一致的名称或编号，能跨页对应。PPT 附录按正文页码与具体结论关联来源及证据局限。知识缺口、目标值及资源尚不明确时，说明需要补齐的证据或决策。

# 模拟知识库导入飞书说明

本说明是可选技术参考，帮助把本地模拟资料放入独立飞书测试空间，供通用 Agent 通过 lark-cli 读取。导入可以手动完成，也可以使用脚本；具体实现由项目组选择。

## 资料与导入形式

| 本地资料 | 建议放入飞书的形式 | 注意事项 |
| --- | --- | --- |
| 24 篇 Markdown 文档 | 云文档，并按主题组织在测试 Wiki 中 | 保留资料编号、日期及虚构标识 |
| U08 访谈台账 CSV | 电子表格 | 保留表头、样本编号及原始内容 |
| K03 路线图 SVG | 文档中的图片；需要研究画板读取时可另建原生画板 | 图片与画板是同一资料的不同呈现，不是两份独立证据 |

模拟资料共 26 项，编号、本地路径与建议资源类型统一见[manifest.json](模拟知识库/manifest.json)。其中的 path 相对“学生材料”目录解析。K03 图片与画板是同一图的呈现选项，按采用的方式导入即可。可先导入当前任务涉及的资料及其引用，再逐步扩展。

E01–E04 是虚构外部来源快照，应保持虚构标识，供模拟竞品材料引用。实际互联网背景研究仍由 Agent 联网开展。

## 导入与资源链接

1. 在自有或获授权的测试 Wiki 中建立专用父节点，与企业生产知识分开。
2. 将所需文档、表格及图表导入，保留资料编号。
3. 记录本地编号对应的实际飞书链接与资源标识；映射按下节记录，由实际创建或查询结果填写。
4. 将文内本地链接替换为同一测试空间中的对应链接。导入竞品材料时一并导入所引用的快照，导入访谈汇总时关联访谈与台账。

例如，C01 引用 E01／E02／E03，C02 引用 E04；K03 的路线图应能从正文打开。未导入的引用需说明不可用，避免留下指向本地机器的失效链接。

## 资源映射

可使用 CSV、JSON 或适合工作流的形式保存实际映射。本包提供本地资料，云端地址与定位标识在部署后获取。

| 信息 | 用途 |
| --- | --- |
| 资料编号与本地路径 | 与 manifest 对应 |
| 资源类型、实际 URL 与定位标识 | 用于读取文档、表格、图片或画板 |
| 父文档／Wiki 节点 | 保留正文与关联资源的关系 |
| 版本或读取时间、读取状态 | 区分更新、成功读取及访问失败 |

文档记录节点与文档对象标识，电子表格记录工作簿及 sheet_id，图片或画板记录素材标识及父文档。只保存适用字段，服务未提供的信息说明原因。文档和素材定位标识可用于获授权的配置；认证凭据不进入分享文件。

## 使用 lark-cli

先查看当前安装版本的帮助，确认可用参数：

```bash
lark-cli --version
lark-cli docs +create --help
lark-cli docs +fetch --help
lark-cli wiki +node-get --help
lark-cli sheets +workbook-info --help
lark-cli sheets +csv-get --help
lark-cli docs +media-preview --help
lark-cli docs +media-download --help
```

使用文档创建命令时，指定实际测试父节点和本地 Markdown 文件，保存返回的链接与资源标识。命令支持 dry-run 时可先预览参数；创建结果不明确时先查找是否已存在，避免重复创建。

文档读取先解析 Wiki 节点对应的对象，再获取正文。正文引用表格时获取实际工作簿和子表标识；引用图像或画板时按资源类型读取。参数以当前版本帮助为准，不凭文件名猜测云端标识。

SVG 若不能直接插入，可转换为图片或按图中内容创建画板，转换后核对文字和依赖关系。

## 导入后查看

选取导入后的文档和关联资源，通过 lark-cli 读取，核对编号、正文、表格数据和图中信息。目录中出现标题并不代表正文已经读到；权限错误也不等于空文档。

若某个资源暂不可读，记录原因与影响；其他可获取的资料可以继续使用。图片和画板分别如实记录读取方式，不将本地读取或其他资源类型的结果记作飞书调用成功。认证凭据保存在运行环境中，不写入可分享文件。

## 方法与页面的对应关系

五看是洞察入口，三定是战略选择的汇总，BLM 贯穿战略设计与执行支撑，DSTE 连接年度计划和执行审视。第 6–7 页支撑“定策略”，第 9 页展开“定目标”，第 10 页展开“定控制点”；创新焦点体现在优先探索的任务机制与反馈方案，不能因加入三定而省略业务设计、人才、组织、氛围与文化。

目标名称或编号在战略选择、任务、资源和验证页面间保持一致。没有目标数值或预算时，不留无解释的空格；说明制定依据、责任岗位、决策节点和条件未满足时的动作。现阶段目标可以是形成可核验的学习、交付与购买证据，不以虚构收入或未经验证的学习提升比例补齐版面。

年度执行由 PPT 的相关页面共同承载：年度任务列明目标、衡量口径、基线或制定依据、岗位、资源及季度里程碑；前 90 天行动按第 1–30／31–60／61–90 天组织，明确验证对象、方法、证据和样本／阈值依据；每季及关键假设或资源变化时开展执行审视，形成继续、调整或停止决策。资源估算标明假设，实验尚未开展时呈现设计。

年度规划需要说明对客户的价值和管理层需要作出的选择。若输入缺少正式愿景或使命，不代企业杜撰口号；依据业务定位组织本轮规划，并说明这一适用边界。

## 引用与证据

样板资料编号对应模拟知识库的 manifest.json，T01 对应模拟年度规划任务卡；公开方法依据见[战略方法与公开来源](../战略方法与公开来源.md)。

来源附录按正文页码、主题和具体结论关联证据，记录资料名称、来源性质及虚构属性、发布与数据日期、读取日期、完整 URL／飞书链接／本地路径及原文位置。涉及共同上游、样本偏差、事实与观点区分、冲突或反例时，说明其对结论的支持范围。来源多时分页呈现，检索调用与失败明细保留在运行记录。页内保留影响判断的业务限制，如样本规模、适用人群、模拟性质及数据时间。

学生正式验收成果使用实际读取的模拟飞书资料和真实联网证据生成，并保留虚构案例标识；后续企业成果使用获授权的真实业务资料。样板中的年龄、建议路径和进度仅为案例示例，不能直接替换公司名称后当作企业战略。没有经营、预算或试点数据时，说明条件与验证动作，不用示意图制造增长趋势。

样板第 16–19 页提供研究判断及来源定位示例，本地资料链接相对 PPT 所在的“输出模板”目录解析。正式联网成果使用实际网页 URL 和沙箱飞书链接，模拟资料仍保留虚构属性。

## 编辑与生成

文字使用原生文本框；比较矩阵使用原生表格；框架和依赖关系使用可编辑形状与连接线。有定量证据时再使用原生图表，保留数据与口径。不要把整页截图放进 PPT 冒充可编辑交付。

工作流可选择适合 Codex 和 Claude Code 的 PPT 生成方式，复用同一份视觉规则。交付时提供生成或更新 PPT 的步骤和所需依赖。PDF 可作为阅读副本，不替代 .pptx。

输出前检查文字溢出、表格列宽、连接线方向、日期和来源对应；中文字体在目标环境中应能正常显示。模拟演示文件保留虚构标识，真实业务输出则使用对应的真实资料范围与状态。

本包提供欢乐互娱的企业需求、公开战略方法说明和模拟开发资料。项目面向 K12 游戏化英语教育，使用通用 Agent 与 lark-cli，至少支持 Codex 和 Claude Code。

## 阅读入口

1. [需求提报表](需求提报表.md)：供社区对接人了解业务背景、项目目标、输入、交付物和评价标准。
2. [学生材料说明](学生材料/README.md)：模拟知识库、任务卡、开发参考和输出模板的使用入口。
3. [战略 PPT 样板](学生材料/输出模板/年度战略草案-橙白框架样板.pptx)：橙白框架风格，可编辑虚构案例。
4. [战略方法与公开来源](学生材料/战略方法与公开来源.md)：公开方法依据及业务适配。

可直接分享本文件夹或完整压缩包。单独转交学生材料时，同时附上根目录提报表；学生版压缩包已包含二者。

## 交付格式

年度战略草案为可编辑 PPT（.pptx），包含研究发现、战略选择、年度推进、首季验证和执行审视，附录保留来源依据。另交付可复用 Agent 工作流、接入说明及运行记录。具体内容与评价要求以根目录提报表为准。

## 项目范围

交付支持 Codex、Claude Code 的战略研究工作流及提报表列出的成果，以模拟飞书沙箱和真实联网完成验收。企业真实知识库试跑属于后续应用。社区导师帮助学生解读需求。

模拟公司、访谈、竞品和测试数字均为虚构；企业内部知识及访问凭据不随包提供。实施顺序、配置和模板用于帮助开发，项目交付标准以提报表为准。

## 切换到真实任务

1. 新建独立运行目录与配置，取消模拟资料输入范围。
2. 使用企业授权的飞书资源映射，不能仅更换公司名称后沿用虚构证据。
3. 按需读取资料与关联表格／图表，保留出处和日期。
4. 区分当前事实、历史讨论、预测和已作决定；对资料冲突先提出解释和必要问题。
5. 企业尚无试点沉淀时，以验证设计和数据采集作为输出，不把模拟库的任何数字填进真实规划。
6. 战略研究同事核查事实与证据，企业指定评审人评价路径取舍和资源建议。

## 最少需要登记的运行信息

- 运行日期、规划起止、资料截止日、研究预算。
- 授权资料范围与当前有效的产品状态说明。
- 需要比较的战略问题、已有承诺或边界；仍开放的事项明确作为研究问题。
- 本轮评审角色、材料用途和可分享范围。

# 开发与运行说明

本说明定义战略 Agent 的运行方式与交付记录，业务要求与 KR 标准见[需求提报表](../需求提报表.md)。随包资料为开发输入与输出参考；项目成果为学生实现的工作流及两端实际运行结果。

## 开发顺序

1. 读取 [T01 模拟任务卡](任务卡/T01-模拟年度规划.md)，用本地模拟资料建立读取、研究、证据整理和战略分析流程。
2. 按[导入说明](模拟知识库导入飞书说明.md)部署独立飞书沙箱，接入真实 lark-cli 与互联网工具。
3. 在 Codex、Claude Code 中分别从原始任务完整运行，处理资料冲突、读取失败和资源约束。
4. 对照提报表整理成果、共用工作流和两端安装、配置、启动及维护说明。

两端共用业务规则、模板与必要脚本，通过工具适配和独立入口处理环境差异。工作流由使用者手动触发，实现形式由项目组选择。

## 运行模式与环境

| 模式 | 资料来源 | 用途 |
| --- | --- | --- |
| offline_fixture | 本地模拟库与虚构外部快照 | 开发解析、推理和输出逻辑 |
| lark_live | 独立飞书沙箱与真实互联网 | 学生正式验收 |
| enterprise_live | 企业授权知识与真实互联网 | 验收后企业应用，使用 [T00](任务卡/T00-企业业务任务说明.md) |

两端需要本地文件和命令访问、联网搜索、网页原文读取、图片理解或可靠的图中文字提取能力，以及可编辑 .pptx 的生成和排版检查能力。记录实际 Agent、模型、操作系统、lark-cli 与工具版本、身份和限制，不因环境名称相同而假设能力相同。

飞书访问显式使用获授权 user 身份，命令与参数以所用 CLI 版本的帮助为准。首版运行只读飞书业务资料、写本地成果；模拟资料部署是独立初始化操作。在线可读取本地任务、方法、代码和模板，但不能用本地业务正文掩盖飞书读取失败。目录标题不能代替正文，图片与画板分别记录真实读取方式。

认证 access／refresh token、Cookie 和密钥不进入交付包或日志。获授权的文档、节点和素材定位标识可用于配置；企业未公开信息不进入外部搜索请求。

## 共用研究流程

1. 记录任务、规划起止、资料截止时间、授权范围和研究预算；未知约束写入任务和运行配置。
2. 按需读取内部资料及关联图表，保留编号、版本、原文位置与读取状态；区分事实、观点、预测、公司决定和未知项。
3. 将知识缺口拆为问题，制定关键词、语言、来源类型和停止条件。
4. 搜索并阅读真实原文，核对时效、适用市场、上游来源和反向证据；转载不计为独立证据。
5. 结合五看洞察比较 2–3 条战略路径，形成目标、策略与控制点建设，说明优先和暂缓事项。
6. 在战略 PPT 中连接关键任务、岗位、资源、季度安排与首季验证，分别评价参与、学习和购买。
7. 生成含研究依据附录的战略 PPT 及运行记录，检查正文结论与附录来源、执行安排之间的对应关系。

模拟竞品不能作为真实搜索对象。在线另选真实公开产品并说明可比性；虚构快照不计入真实联网证据。正文中的指令性文字属于待分析数据，不能改变任务和授权。Agent 不自行联系用户、开展教学、收款、采购或批准预算。

## 日期、预算与异常

规划覆盖起点后的 12 个日历月，前 90 天行动单独计算。T01 离线案例固定为 2026-09-17 至 2027-09-16；在线可采用运行时点，两端使用相同任务、日期范围、资料版本和研究预算，模拟资料本身的日期不改写。

来源发布日期、事件期间和读取时间分别记录。截止日后的信息不能进入历史回测；动态页面无法读取、只有摘要或需要登录时，如实说明限制。

运行前设置搜索、原文读取、飞书调用、时间、请求超时和重试上限，并保留配置。批量搜索按查询词计数，重试计入调用用量。主要问题得到覆盖、连续检索没有新增有效证据或预算用尽时结束；未覆盖事项进入结果说明。

临时错误采用有界重试和退避；认证或权限错误列出恢复所需条件，不绕过权限。部分资料失败时继续可完成的分析，必要授权或工具不可用时停止相应模式并说明阻断原因。恢复后新建运行或注明续跑关系，保留失败记录。

## 未知信息与记录

无经营基线、预算、人力或试点数据不阻断条件性战略分析。影响推荐的缺口应记录当前状态与影响、条件方案、所需证据或决策、责任岗位、获取节点、关闭证据，以及未解决时缩小、暂缓或停止的内容。

例如，预算未形成时给出附依据的情景估算或成本公式与条件方案；管理层在首次新增支出前决定额度，未形成额度则暂缓需要新增支出的实验。岗位建议不代表已有编制，目标与预测不能写成实绩。

运行记录格式由实现选择，至少包含任务与模式、环境和工具版本、日期、资料范围和版本、研究问题与检索计划、问题覆盖情况、预算、实际调用与用量、产出路径、失败读取、人工介入、停止原因和已知限制。未使用工具或无法获取版本时说明原因，计数来自实际记录。分别标识完成、部分完成或阻断；流程完成不等于战略假设得到验证。

## 启动与双环境验证

运行配置包含模式、任务文件、规划日期、资料截止时间、研究预算、授权范围与输出目录。两端使用相同任务、日期、资料版本和预算，在独立任务及结果目录中运行。离线开发读取本地 manifest 与虚构快照；正式验收读取实际飞书资源映射并开展真实联网研究。

两端各自从原始资料生成含研究依据附录的战略 PPT，保留完整调用与异常记录。推荐和文字可以不同，评价采用相同的 KR1／KR2／KR3 标准。共同工作流及该端记录构成交付物 2 的评价依据。

| 验证内容 | 记录与判断依据 |
| --- | --- |
| 完整运行与信息增量 | 实际联网、原文和飞书关联资源读取记录；新增信息、五看三定、正文结论与证据附录的对应关系 |
| 证据与数据缺口 | 同源、过期、冲突、空研究入口及无经营基线的处理；输入文字未改变任务或权限 |

| 异常处理 | 两端分别记录授权过期、权限不足、限流和不可访问的验证结果；重试有上限，失败有原因及恢复条件 |
| 迁移与约束变化 | 更换同类议题或目标市场、调整资源约束后的结果；核心工作流共用，策略随证据和约束变化 |

# 华为战略方法调研与游戏化英语教育应用

调研日期：2026-09-17。用途：为 FDE X 企业年度战略 Agent 项目提供方法依据及业务适配说明。

企业面向 K12 英语教育，以游戏化方式开展教学，采用研运一体模式。战略研究同事通过通用 Agent 开展研究，至少支持 Codex 和 Claude Code；企业知识库维护在飞书云文档与 Wiki 中，由 lark-cli 访问。项目重点是建立结构化的互联网背景研究流程，并将研究结果与企业知识结合，用于公司级年度战略规划。

## 1. 项目定位

**游戏化英语教育公司年度战略 Agent（通用 Agent + lark-cli）**。

核心业务链路：提出公司年度战略任务 → 盘点企业已有知识 → 自动开展市场、用户、竞品标杆及 AI 背景研究 → 核验与整合证据 → 比较战略方向 → 输出包含年度执行与验证安排的战略 PPT，附录保留研究依据。

现有知识来源包括竞品调研 Wiki、用户调研 Wiki、行业信息 Wiki、竞品分析、AI 前沿信息、内部产品知识和项目复盘。已有知识用于明确研究起点；Agent 需要主动补充新资料、核对时效并识别知识缺口。

公司处于研发／免费试点阶段，尚未沉淀产品试点数据及经营、预算、人力资料。规划为启动日起未来 12 个月；现有长期路线图可重议。无经营基线时，业绩差距不能凭空量化，应侧重机会假设、能力缺口及分阶段验证。

规划以公司整体为对象，将客群与市场、学习价值、产品、增长、商业模式、AI 应用和组织能力联系起来。最终战略选择与资源承诺由管理层作出。

## 2. 公开战略方法依据

### 2.1 客户价值、战略聚焦与边界

华为发布 2017 年年报时强调，关注客户数字化转型中的现实挑战，帮助客户解决问题并实现商业成功。[华为：2017 年年报发布说明](https://www.huawei.com/cn/news/2018/3/huawei-2017-annual-report)

华为 2017 年年报中的战略说明明确表达业务聚焦，以及做什么和不做什么的边界。该材料反映当时战略，不作为今天各业务范围的判断。[华为 2017 年年度报告，英文版正文第 3 页](https://www.huawei.com/-/media/corporate/pdf/annual-report/annual_report2017_en.pdf)

**本项目的转化建议**： 每个候选方向必须说明服务哪类学习者、解决什么学习问题、靠什么形成差异，以及暂缓什么。仅写“打造优质教育产品”“拥抱 AI”“全球化布局”不构成可评审的选择。

### 2.2 BLM：把战略设计与执行条件放在一起

IBM 的原始资料给出了 Business Leadership Model：战略侧包括市场洞察、战略意图、创新焦点、业务设计；执行侧包括关键任务及依赖、人才、正式组织、氛围与文化，并连接市场结果和差距。领导力与价值观贯穿其中。因此，BLM 不能被标为华为原创。 [IBM Redbooks，图 1-2，正文第 5 页](https://www.redbooks.ibm.com/redpapers/pdfs/redp4374.pdf)

关于 IBM 实践的研究进一步区分：业绩差距是预期与实际结果的差异；机会差距是现有业务与可通过新业务设计获得的结果之间的差异。 [Harreld、O’Reilly、Tushman：Dynamic Capabilities at IBM，2007](https://digicoll.lib.berkeley.edu/record/284764/files/991056723509706532_C095180123_49_4.pdf)

**本项目的转化建议**： 先判断议题是改善现有教育业务表现，还是探索新的增长机会，再检查对应能力与资源。“获客成本高”本身不足以支持开发新产品的结论。本项目依据公开可核验的框架设计分析流程，不涉及华为内部模板。

### 2.3 五看三定：便于组织调研的问题清单

公开咨询资料通常将“五看”概括为看行业／趋势、看市场／客户、看竞争、看自身、看机会；“三定”的常见表述是定目标、定策略、定控制点。不同公开材料措辞并不完全一致。本项目采用这一公开实践口径组织提问与分析。 [安谋咨询：五看三定方法论解读（二手资料）](https://www.niuhrd.com/articles/shen-du-chai-jie-hua-wei-zhan-lve-dong-cha-he-zhan-lve-gui-hua-wu-kan-san-ding-fang-fa-lun)

“控制点”在本项目中解释为支撑持续差异化的关键能力或资源，例如内容生产能力、学习者社区与服务能力或渠道能力。它不是报告里随意填入的一句“建立壁垒”，需要已有证据或建设计划。

### 2.4 DSTE：战略要落到年度计划、预算和复盘

华为 2017 年年报直接说明：DSTE 管理体系通过愿景牵引战略，让战略驱动年度业务计划、预算和绩效，并通过战略解码与执行审视推动落地。 [华为 2017 年年度报告，英文版正文第 122 页](https://www.huawei.com/-/media/corporate/pdf/annual-report/annual_report2017_en.pdf)

**本项目的转化建议**： 输出必须连接到目标、任务、岗位、资源、时间和复盘条件。首版只形成这些内容的建议稿，公司年度目标需连接季度里程碑与首季验证。年度规划和 90 天行动安排属于本项目的业务设计，并非华为固定规范。

### 2.5 四组概念如何连接

五看用于洞察，三定用于归纳战略选择；BLM 将这些选择与战略意图、创新焦点、业务设计及执行支撑连接；DSTE 将选择解码到年度计划、预算、组织目标和执行审视。它们在本项目中形成一条分析链，不是四套相互独立、重复填写的表格。

三定需要相互匹配：目标说明预期结果和衡量方式；策略说明实现路径、备选比较及不做事项；控制点说明支撑持续差异化的关键能力或资源、现状证据、建设动作及证明标准。控制点不是项目进度检查点，普通功能也不自动构成竞争优势。

本项目处于研发／免费试点阶段，不强行套用成熟企业的收入指标、预算体系或组织规模。管理层承担战略取舍和资源决策，岗位建议不等于实际编制。用指标口径、基线建立方案、条件投入和季度审视形成可执行的首版；目标、判据和资源未形成时，明确制定岗位、决策节点和未形成时的处理。

## 3. 战略方法如何用于 K12 游戏化英语教育

以下为项目适配设计，不是华为内部流程复刻，也不构成对某一教育产品学习效果的判断。

| 视角 | 研究重点 | 需要形成的判断 |
| --- | --- | --- |
| 行业／趋势 | 英语教育需求、教育科技与 AI 变化、目标市场环境 | 哪些变化影响公司的年度选择，哪些仅是短期热点 |
| 市场／用户 | 学习者年龄与能力、学习场景、使用障碍、付费及决策角色 | 服务谁、解决什么学习问题、如何验证学习与购买价值 |
| 竞争／标杆 | 同类教育产品、替代学习方式、值得借鉴的产品或运营机制 | 用户为什么选择我们；标杆哪些做法适用、哪些条件不具备 |
| 自身 | 产品知识、教研与研发能力、运营能力、项目复盘、经营与资源约束 | 哪些优势已得到验证，哪些能力要补，能支持多大范围的投入 |
| 机会 | 将外部证据与内部能力关联 | 本年度应优先投入、先验证、暂缓或放弃什么 |

研究必须区分三类结果：**学习结果**、**使用参与** 和 **经营表现**。它们可能相互影响，但不能直接互相替代。例如，用户愿意多玩一段时间不等于英语能力已提升；访谈中表达喜欢也不等于愿意持续付费。

学习者、实际使用者和付费决策者可能不同。依据本轮用户研究识别这些角色，不预设家长、学校或学习者本人是唯一购买方。研究任务写清候选地区、学段和收费路径；没有定下的事项进入比较，不要求先作出战略选择才启动研究。

## 4. 互联网背景研究的结构化流程

| 环节 | 工作要求 | 输出 |
| --- | --- | --- |
| 研究任务定义 | 明确规划年度、战略问题、市场、客群、截止日与检索预算 | 年度任务卡与问题清单 |
| 内部知识盘点 | 检索相关 Wiki，分清事实、旧判断和未验证假设 | 已有知识摘要与缺口 |
| 研究计划 | 将缺口拆成子问题，设关键词、语言、来源类型和完成条件 | 可执行检索计划 |
| 外部检索与阅读 | 自动找来源并读取原文；搜索摘要用于定位线索 | 原始来源记录与摘录 |
| 核验与去重 | 识别转载、过期资料、宣传内容、样本与口径差异 | 可用事实、冲突与适用范围 |
| 结构化整理 | 将发现关联研究问题、飞书知识及原始依据 | 研究发现与 PPT 证据附录 |
| 战略解释 | 说明对公司的机会、威胁和关键假设 | 年度规划输入与验证问题 |

PPT 来源附录至少记录：来源编号、标题、URL／飞书文档链接、发布者、发布日期、事件或数据期间、读取时间、原文位置、适用市场与用户、支持的事实、限制。时间未知时明确标注，不以访问日期代替发布日期。

关键判断优先依靠原始研究、主管机构公开资料、产品官方文档和正式披露。多家媒体转述同一上游材料不构成多份独立证据；只有单一来源的判断需保留局限。公开评论补充用户线索，但不替代企业真实用户调研，也不触发自动联系受访者。

研究按问题覆盖与增量价值停止：完成主要问题、连续检索无新增有效证据，或达到本轮任务预算时结束，报告未覆盖事项。不得为了数量凑来源，也不得因存在知识缺口无限检索。

每次运行生成独立战略 PPT 和运行记录，保留资料时间范围及来源，不自动覆盖原 Wiki。首版由战略研究同事手动触发；有新证据或约束变化时发起新运行，不要求后台定时监控。

## 5. 从背景研究进入公司年度规划

1. **识别核心差距**：区分当前业务表现问题与新增机会，避免从某条热点直接跳到公司战略。
2. **设定战略议题**：把背景发现转成必须作出的选择，例如优先服务哪个细分客群、优先改善哪类学习价值、哪种 AI 能力值得投入。
3. **比较备选路径**：对重要议题提出 2–3 个不同选项，比较用户价值、经营逻辑、能力匹配、投入和风险；证据不足时先安排验证。
4. **形成公司年度主线**：明确优先事项和不做事项，检查产品、增长、技术与组织是否争用同一资源。
5. **建立目标与推进安排**：年度目标对应关键任务、季度里程碑、负责人岗位和资源条件；目标数值须有依据；无法确定时在战略 PPT 中说明制定责任、节点及未形成目标时的处理，依据列入 PPT 附录。
6. **制定首季验证**：围绕影响年度取舍的关键假设安排前 90 天行动，说明何时继续、调整或停止投入。

**虚构示例**：公开资料显示某标杆增加了 AI 互动练习，内部用户研究提示反馈不够及时。可以据此提出“即时反馈是否能改善目标学习任务”的假设，安排小规模验证；不能仅凭标杆发布了功能就判断本公司应全面投入，也不能将互动次数当成学习效果。

### 年度战略成果的组织方式

成果按公开 BLM 的战略设计和执行要素组织，并结合华为公开 DSTE 原则连接年度计划。以下为本项目的交付结构，不是华为内部模板。

| 方法环节 | 具体输出 |
| --- | --- |
| 业绩／机会差距 | 当前结果与目标差距、潜在机会及依据；无数据时保留待验证问题 |
| 市场洞察 | 五看研究结论、机会与威胁、关键证据和冲突 |
| 三定与战略意图 | 年度方向、目标口径与成功判据、实现策略及取舍、控制点与能力建设路径 |
| 创新焦点 | 学习体验、产品、技术或商业模式的重点突破与试验 |
| 业务设计 | 客户选择、价值主张、价值获取、活动范围及持续优势 |
| 关键任务与依赖 | 将业务设计拆成关键举措，说明先后关系和跨岗位依赖 |
| 执行支撑 | 组织职责、人才与能力缺口、需要建立的协作机制和文化行为 |
| 年度业务计划与执行审视 | 指标基线与目标、预算人力、季度里程碑、首季行动；对照目标与实际审视偏差，调整路径与资源并保留依据 |

战略草案以可编辑 PowerPoint（.pptx）交付，包含战略总览、按上述逻辑展开的分析页面，以及相互对应的年度计划和资源表。不能仅罗列框架名称：每项选择必须说明依据、放弃的选项和执行条件；目标、任务、责任岗位、资源及复盘使用一致的名称或编号，能跨页对应。PPT 附录按正文页码与具体结论关联来源及证据局限。知识缺口、目标值及资源尚不明确时，说明需要补齐的证据或决策。

# 模拟知识库导入飞书说明

本说明是可选技术参考，帮助把本地模拟资料放入独立飞书测试空间，供通用 Agent 通过 lark-cli 读取。导入可以手动完成，也可以使用脚本；具体实现由项目组选择。

## 资料与导入形式

| 本地资料 | 建议放入飞书的形式 | 注意事项 |
| --- | --- | --- |
| 24 篇 Markdown 文档 | 云文档，并按主题组织在测试 Wiki 中 | 保留资料编号、日期及虚构标识 |
| U08 访谈台账 CSV | 电子表格 | 保留表头、样本编号及原始内容 |
| K03 路线图 SVG | 文档中的图片；需要研究画板读取时可另建原生画板 | 图片与画板是同一资料的不同呈现，不是两份独立证据 |

模拟资料共 26 项，编号、本地路径与建议资源类型统一见[manifest.json](模拟知识库/manifest.json)。其中的 path 相对“学生材料”目录解析。K03 图片与画板是同一图的呈现选项，按采用的方式导入即可。可先导入当前任务涉及的资料及其引用，再逐步扩展。

E01–E04 是虚构外部来源快照，应保持虚构标识，供模拟竞品材料引用。实际互联网背景研究仍由 Agent 联网开展。

## 导入与资源链接

1. 在自有或获授权的测试 Wiki 中建立专用父节点，与企业生产知识分开。
2. 将所需文档、表格及图表导入，保留资料编号。
3. 记录本地编号对应的实际飞书链接与资源标识；映射按下节记录，由实际创建或查询结果填写。
4. 将文内本地链接替换为同一测试空间中的对应链接。导入竞品材料时一并导入所引用的快照，导入访谈汇总时关联访谈与台账。

例如，C01 引用 E01／E02／E03，C02 引用 E04；K03 的路线图应能从正文打开。未导入的引用需说明不可用，避免留下指向本地机器的失效链接。

## 资源映射

可使用 CSV、JSON 或适合工作流的形式保存实际映射。本包提供本地资料，云端地址与定位标识在部署后获取。

| 信息 | 用途 |
| --- | --- |
| 资料编号与本地路径 | 与 manifest 对应 |
| 资源类型、实际 URL 与定位标识 | 用于读取文档、表格、图片或画板 |
| 父文档／Wiki 节点 | 保留正文与关联资源的关系 |
| 版本或读取时间、读取状态 | 区分更新、成功读取及访问失败 |

文档记录节点与文档对象标识，电子表格记录工作簿及 sheet_id，图片或画板记录素材标识及父文档。只保存适用字段，服务未提供的信息说明原因。文档和素材定位标识可用于获授权的配置；认证凭据不进入分享文件。

## 使用 lark-cli

先查看当前安装版本的帮助，确认可用参数：

```bash
lark-cli --version
lark-cli docs +create --help
lark-cli docs +fetch --help
lark-cli wiki +node-get --help
lark-cli sheets +workbook-info --help
lark-cli sheets +csv-get --help
lark-cli docs +media-preview --help
lark-cli docs +media-download --help
```

使用文档创建命令时，指定实际测试父节点和本地 Markdown 文件，保存返回的链接与资源标识。命令支持 dry-run 时可先预览参数；创建结果不明确时先查找是否已存在，避免重复创建。

文档读取先解析 Wiki 节点对应的对象，再获取正文。正文引用表格时获取实际工作簿和子表标识；引用图像或画板时按资源类型读取。参数以当前版本帮助为准，不凭文件名猜测云端标识。

SVG 若不能直接插入，可转换为图片或按图中内容创建画板，转换后核对文字和依赖关系。

## 导入后查看

选取导入后的文档和关联资源，通过 lark-cli 读取，核对编号、正文、表格数据和图中信息。目录中出现标题并不代表正文已经读到；权限错误也不等于空文档。

若某个资源暂不可读，记录原因与影响；其他可获取的资料可以继续使用。图片和画板分别如实记录读取方式，不将本地读取或其他资源类型的结果记作飞书调用成功。认证凭据保存在运行环境中，不写入可分享文件。

# 战略 PPT 排版说明

## 方法与页面的对应关系

五看是洞察入口，三定是战略选择的汇总，BLM 贯穿战略设计与执行支撑，DSTE 连接年度计划和执行审视。第 6–7 页支撑“定策略”，第 9 页展开“定目标”，第 10 页展开“定控制点”；创新焦点体现在优先探索的任务机制与反馈方案，不能因加入三定而省略业务设计、人才、组织、氛围与文化。

目标名称或编号在战略选择、任务、资源和验证页面间保持一致。没有目标数值或预算时，不留无解释的空格；说明制定依据、责任岗位、决策节点和条件未满足时的动作。现阶段目标可以是形成可核验的学习、交付与购买证据，不以虚构收入或未经验证的学习提升比例补齐版面。

年度执行由 PPT 的相关页面共同承载：年度任务列明目标、衡量口径、基线或制定依据、岗位、资源及季度里程碑；前 90 天行动按第 1–30／31–60／61–90 天组织，明确验证对象、方法、证据和样本／阈值依据；每季及关键假设或资源变化时开展执行审视，形成继续、调整或停止决策。资源估算标明假设，实验尚未开展时呈现设计。

年度规划需要说明对客户的价值和管理层需要作出的选择。若输入缺少正式愿景或使命，不代企业杜撰口号；依据业务定位组织本轮规划，并说明这一适用边界。

## 引用与证据

样板资料编号对应模拟知识库的 manifest.json，T01 对应模拟年度规划任务卡；公开方法依据见[战略方法与公开来源](../战略方法与公开来源.md)。

来源附录按正文页码、主题和具体结论关联证据，记录资料名称、来源性质及虚构属性、发布与数据日期、读取日期、完整 URL／飞书链接／本地路径及原文位置。涉及共同上游、样本偏差、事实与观点区分、冲突或反例时，说明其对结论的支持范围。来源多时分页呈现，检索调用与失败明细保留在运行记录。页内保留影响判断的业务限制，如样本规模、适用人群、模拟性质及数据时间。

学生正式验收成果使用实际读取的模拟飞书资料和真实联网证据生成，并保留虚构案例标识；后续企业成果使用获授权的真实业务资料。样板中的年龄、建议路径和进度仅为案例示例，不能直接替换公司名称后当作企业战略。没有经营、预算或试点数据时，说明条件与验证动作，不用示意图制造增长趋势。

样板第 16–19 页提供研究判断及来源定位示例，本地资料链接相对 PPT 所在的“输出模板”目录解析。正式联网成果使用实际网页 URL 和沙箱飞书链接，模拟资料仍保留虚构属性。

## 编辑与生成

文字使用原生文本框；比较矩阵使用原生表格；框架和依赖关系使用可编辑形状与连接线。有定量证据时再使用原生图表，保留数据与口径。不要把整页截图放进 PPT 冒充可编辑交付。

工作流可选择适合 Codex 和 Claude Code 的 PPT 生成方式，复用同一份视觉规则。交付时提供生成或更新 PPT 的步骤和所需依赖。PDF 可作为阅读副本，不替代 .pptx。

输出前检查文字溢出、表格列宽、连接线方向、日期和来源对应；中文字体在目标环境中应能正常显示。模拟演示文件保留虚构标识，真实业务输出则使用对应的真实资料范围与状态。

## 第五部分 · 目标 O（Objective）

面向游戏化英语教育公司的战略研究岗位，建立兼容 Codex、Claude Code 的通用 Agent 工作流，将真实联网研究与 lark-cli 获取的飞书知识转化为有依据、有取舍、可执行和复盘的公司年度战略 PPT，包含研究依据、战略选择和年度执行与验证安排。

## 第六部分 · KR 验收标准

学生项目以模拟飞书沙箱和真实联网结果验收；Codex、Claude Code 两端分别按 KR1／KR2／KR3 评价。KR1 对应两项交付物，KR2 评价战略 PPT 的业务质量，KR3 评价工作流的实际使用表现。

### KR1 · 交付内容（系统固定，无需填写）

每一项交付物都会被检查 3 个维度：

| 维度 | 检查什么 |
| --- | --- |
| 完整度 | 该交付的内容是否齐全、核心指标项有无缺失 |
| 准确度 | 是否符合原始资料与业务规则，无严重逻辑漏洞 |
| 格式规范 | 是否按约定格式交付且能正常打开使用 |

均分 = 得分总和 ÷ （交付物数量 × 3），每项 1–5 分。

### KR2 · 业务质量

业务质量由企业侧评价，战略研究同事核对证据。

#### 维度 1

| 项目 | 填写 |
| --- | --- |
